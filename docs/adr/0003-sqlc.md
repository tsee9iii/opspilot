# ADR-0003: SQLC for Database Access

## Status

Accepted

## Context

Central owns the PostgreSQL schema and command queue. We want compile-time
checked, type-safe queries with no ORM magic, and a single source of truth for
schema and queries. Queries such as the atomic lease (`FOR UPDATE SKIP
LOCKED`) and conditional state transitions must be hand-written SQL, not
framework abstractions.

## Decision

Use sqlc (v1.31.1) with the `pgx/v5` backend.

- Schema: `sql/migrations/0001..0005` (the authoritative DDL)
- Queries: annotated SQL in `sql/queries/`, each named via `-- name:`
- Generated code: `gen/postgresql`, checked in, regenerated with
  `sqlc generate` (`make sqlc-generate`)
- Overrides map `timestamptz → time.Time` and `uuid → google/uuid.UUID`
- Migrations are static files; sqlc reads them only to infer types

## Consequences

- Queries are generated, typed, and fail to compile if the schema no longer
  matches.
- The raw SQL (and the lease/transition `WHERE` semantics) is visible and
  reviewable; no ORM abstraction hides it.
- Generated code is committed, so builds are deterministic without running
  sqlc.
- Adding or changing a query requires editing SQL and regenerating; there is
  no runtime query builder.
- Transaction-spanning writes require explicit `pgx` handling rather than an
  ORM unit-of-work API.
