# ADR-0004: Agent Authentication

## Status

Accepted (updated for HMAC request signing, 2026)

## Context

Agents register once and then authenticate subsequent calls (heartbeat,
capability sync, command lease/start/complete/fail). Three problems must be
solved:

1. **Replay resistance for registration** — a registration token seen in
   transit or logs must not be usable twice.
2. **Secrets at rest** — plaintext agent secrets must never be stored in
   PostgreSQL, and a database dump must not expose credentials that work
   against the API.
3. **Per-request authenticity** — a request claiming to come from an agent must
   be provably generated by that agent, must be bound to the exact request
   (method, path, body), and must not be replayable within the freshness
   window.

## Decision

- **Registration tokens** are stored only as
  `HMAC-SHA256(OPSPILOT_AUTH_SERVER_SECRET, token)` hex, never as plaintext.
  The server secret defaults to `dev-only-secret-change-me` and is read from
  `OPSPILOT_AUTH_SERVER_SECRET`.
- **Consumption** is atomic: registration `DELETE`s the token row in the same
  unit of work; a replay returns `409 token_already_used`.
- **Per-agent signing keys**: registration generates a random 32-byte signing
  key (`internal/agentsign.NewSigningKey`), returns it once to the agent, and
  stores it in `agents.signing_key` for verification. The agent persists it via
  its config.
- **Every post-registration agent request is HMAC-signed** over the canonical
  string `agent_id "\n" timestamp "\n" nonce "\n" method "\n" path "\n" body`
  (`internal/agentsign`), sent via `X-Agent-Id`, `X-Agent-Timestamp`,
  `X-Agent-Nonce` and `X-Agent-Signature` headers. Central verifies the
  signature constant-time, rejects timestamps outside the 5-minute window, and
  rejects replayed nonces via an in-memory cache.
- **Operator endpoints** (`POST /api/v1/commands/approve`,
  `GET /api/v1/commands/{id}`) require a bearer operator token
  (`OPSPILOT_OPERATOR_TOKEN`), verified with a constant-time comparison.
- The legacy Argon2id `secret` hash is retained at rest for backwards
  compatibility but is no longer verified on a per-request basis.
- Failed identity/signature checks return `401` with a structured error code
  (`invalid_signature`, `expired_timestamp`, `invalid_credentials`,
  `replay_detected`).

## Consequences

- Registration tokens cannot be replayed even if captured.
- No plaintext credentials are persisted; a database leak does not yield
  working agent secrets.
- Signatures are bound to the request method, path and body, so a captured
  signature cannot be replayed against a different request, and the nonce cache
  stops exact replays within the freshness window.
- Per-request verification is cheap (one HMAC-SHA256) compared with the
  Argon2id cost the secret model paid on every heartbeat and capability sync.
- HMAC verification is centralized in `internal/agentsign`, shared by both
  binaries, so the signing contract cannot drift between agent and central.
- A misconfigured agent that loses its `agent_id` or `signing_key` must be
  re-provisioned with a fresh registration token.
